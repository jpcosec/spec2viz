Vista 03 · Diagrama de secuencia

El viaje de un mensaje, de punta a punta

Los tres caminos posibles de cada mensaje: respuesta conforme, baja confianza con escalamiento humano, y sospecha de evento adverso que deriva al safety-net. La respuesta visual a "walk me through a message".

sequenceDiagram
    autonumber
    actor HCP as HCP
    participant Meta as Meta Cloud API
    participant BSP as ManyChat BSP
    participant CF as Cloudflare
    participant Pre as Pre-guardrails
    participant RAG as RAG (KB MLR)
    participant LLM as Bedrock + Claude
    participant Post as Post-guardrails
    participant DB as PostgreSQL
    participant S3 as S3 Audit WORM
    HCP->>Meta: Mensaje WhatsApp (TLS)
    Meta->>BSP: Webhook
    BSP->>CF: Forward
    CF->>Pre: Request filtrado
    Pre->>RAG: Consulta validada
    RAG->>LLM: Contexto MLR + consulta
    LLM-->>Post: Respuesta candidata
    alt Conforme
        Post->>DB: Persistir conversación
        Post->>S3: Audit pseudonimizado
        Post->>BSP: Reply flow
        BSP->>Meta: Enviar
        Meta->>HCP: Respuesta
    else Baja confianza
        Post->>DB: Marcar escalamiento
        Note over Post,DB: Takeover humano vía consola
    else Sospecha AE
        Post->>S3: Flag + audit WORM
        Note over Post,S3: Deriva a AE Safety-net
    end
Vista 04 · Diagrama de secuencia

AE Safety-net: los cinco pasos

Obligación de canal, no sistema de farmacovigilancia: detección, flag pseudonimizado, notificación externa, takeover humano, y gestión del caso por Teva fuera de la infraestructura antonIA.

sequenceDiagram
    autonumber
    actor HCP as HCP
    participant Pipe as Pipeline
    participant AE as AE Safety-net
    participant S3 as S3 WORM
    participant Ops as Consola antonIA
    participant PV as Teva PV designee
    HCP->>Pipe: Mensaje con posible AE
    Pipe->>AE: Señal de sospecha
    AE->>S3: Flag + audit pseudonimizado
    AE->>PV: Notificación email / Slack externo
    AE->>Ops: Human takeover
    Ops->>HCP: Conversación asistida
    Note over PV: Teva PV gestiona el caso manualmente,
fuera de infraestructura antonIA
    Note over AE: Piloto: escalamiento + log.

Vista 06 · Diagrama de estados

El ciclo de vida del consentimiento

Desde el opt-in (base Teva o in-channel) hasta el borrado por DSR, pasando por los dos niveles de opt-out: por campaña, que mantiene elegibilidad futura, y por canal, acotado a WhatsApp.

stateDiagram-v2
    [*] --> SinContacto
    SinContacto --> OptIn : Base Teva o in-channel
    OptIn --> Activo : Primera campaña
    Activo --> Activo : Campañas (máx 4/mes)
    Activo --> OptOutCampana : Opt-out de campaña
    OptOutCampana --> Activo : Elegible para otras campañas
    Activo --> OptOutCanal : Block / report / opt-out
    OptOutCampana --> OptOutCanal : Señal de canal
    OptOutCanal --> Activo : Re-opt-in explícito
    Activo --> Borrado : DSR erasure
    OptOutCanal --> Borrado : DSR erasure
    Borrado --> [*]
